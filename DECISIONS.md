# Design and technical decisions

_Generated by the Niobium FHE Application Design AI Assistant (FHEanna)._

Version 1, 2026-09-25.

## Privacy model
- **Parties.** A trusted local client on the quiz taker's computer (`client_service.py` and the `era_keygen` / `era_encrypt` / `era_decrypt` programs it runs; the browser page is not the cryptographic client) and a scoring service (compute). The compute side is treated as honest-but-curious: it runs the code faithfully but would read anything it could.
- **What stays private from compute:** the answers, the trait vector, all 12 scores, and the final era. Compute sees only the ciphertext itself, its size, how long the math took, and when each request happened.
- **Keys.** The client makes one CKKS key pair when the client service starts; every quiz shares it until the service restarts. Only the crypto context (`cc.bin`) and rotation keys (`rk.bin`) go to compute. The public key used to be sent too, but was dropped in v1.2 because `era_server` never reads it. The secret key is never sent to compute and stays in the owner-only client home.
- **Enforced, not just claimed.** `era_server` exits if a file named `sk.bin` is in its folder; the compute service refuses to start with one anywhere under its home and only accepts `cc.bin` and `rk.bin` as uploads. These are tripwires, not isolation: locally both programs run as the same user, so the separation is by design, not by the operating system. (v1 also had a Docker setup with client and compute in separate containers; it was never re-tested after the native macOS work and is not included in this repository.)
- **Output privacy.** The client decrypts all 12 scores and picks the top one itself (no encrypted comparison or argmax). The era profiles are public quiz content, so the client learning them costs nothing.

## Quiz math
- **8 traits:** Sparkle, Heartache, Edge, Nostalgia, Romance, Hush, Drama, Roots. Eight is a power of two, which keeps the encrypted summing step to 3 rotations.
- **12 questions** (v2), 4 options each. Each option nudges 2 to 4 traits. (v1 had 10 questions; see "Content and design v2" below.)
- **Trait vector** = sum of the chosen options, minus a fixed baseline (the average answer sheet), scaled to length 1. Subtracting the baseline was needed: without it, one era won 35% of all possible answer sheets because every sheet leaned toward the most common traits.
- **12 eras**, Debut through The Life of a Showgirl, each an 8-number profile scaled to length 1.
- **Score** = dot product of the two unit vectors (cosine similarity). The page shows it as a match percentage, 50 x (1 + score).
- **Balance.** I hand-wrote the profiles, then ran a small bounded search (each value moved by at most 0.3) so that over all 1,638,400 possible v1 answer sheets every era won between 8.2% and 8.6%. The profiles were then frozen; v2 balanced the answers instead (7.4-9.2%). Spot checks of "obvious" answer sheets land where a fan would expect (all cozy/woods answers give folklore or evermore, sequins and synths give Showgirl, 1989 or Lover).
- **Known quirk.** folklore and evermore are close cousins (profile similarity 0.93), so they often finish 1-2. 0.6% of answer sheets have a top-two gap under 0.001; encryption noise (~1e-10) is far below that, so it never changes a result.

## Encrypted circuit (CKKS)
- **One ciphertext up, one down.** The client copies its 8 numbers into 12 blocks (96 slots). Compute multiplies by a plaintext holding the 12 era profiles in the same layout, then rotates-and-adds by 1, 2, 4, so slot 8e holds era e's score. Depth 1, 3 rotations, no bootstrapping.
- **Parameters.** Ring dimension 2^16 (the size Niobium documents for the Fog), multiplicative depth 1, 50-bit scaling, 60-bit first modulus, 128-bit security enforced by OpenFHE. The result is compressed to one tower before it goes back.
- **Sizes and speed (measured).** Query ciphertext 2.10 MB, result 1.05 MB, crypto context 0.6 KB and rotation keys 18.9 MB (one-time). Keygen ~0.25 s, encrypt ~0.1 s, server ~0.2 s (CPU) or ~0.5 s (simulator), decrypt ~0.08 s, peak server memory ~90 MB.
- **One circuit function** (`run_circuit` in `app/common.hpp`) is called by every mode, so CPU, simulator and Fog runs cannot diverge.

## Niobium tooling
- Followed the `fhe-application-design` skill (v0.13.0): faithful twin first, four programs (keygen/encrypt/server/decrypt), two homes, `run_test.sh` with `--cpu`, `--sim`, `--sim-full` and the Fog default, the no-secret-key guard and negative test.
- Chose the **OpenFHE C++ path** over the alpha `nb` DSL: the circuit is tiny, and the C++ path is the one with documented `niobium::compiler()` recording and `fog submit` dispatch.
- Recording pattern copied from niobium-client's `plaintext_add` and `mult` examples (`capture_crypto_context`, `tag_input` for the query and the era plaintext, `tag_keys` for the rotation keys, hollow recording, `replay()`, `result()`).
- Fog dispatch uses the documented `fog submit <server> <home> --hollow --target=FOG`; nothing Fog-specific was invented.

## UI and wiring
- The browser talks to a small client service on the same computer; that service is the trusted client in this version. It does the encryption and decryption with the Niobium build of OpenFHE.
- The pipeline view shows only real data from the run: the trait numbers, a hex slice of the actual ciphertext bytes plus its SHA-256 and a download link, the compute service's own log (sizes, timing and a shortened session ID only), the server time, and the 12 decrypted scores.
- The page labels which backend did the encrypted math (CPU, Niobium simulator, or Fog) and says plainly when the Fog is not connected.
- Design (v1, replaced in v2): warm paper background, a 12-color "spine" strip as the era motif, one color per era (original palette, no official artwork, lyrics, photos or logos). Copy follows the project's writing rules (no em dashes).

## Native macOS build (2026-09-27)
- **Where:** Apple Silicon Mac (arm64, macOS 26.6, AppleClang 16, 8 GB RAM), no Docker.
- **Recipe source.** The skill's `environment-setup.md` (v0.13.0 copy here) has no native / "Path B" section, only Docker. So the native steps come from niobium-client's own README (macOS prerequisites) plus the skill's Dockerfile (which submodules and make targets to use). Nothing new was invented.
- **niobium-client:** fresh `git clone https://github.com/NiobiumInc/niobium-client` (main @ `9357ad5`), then `git submodule update --init --recursive vendor/niobium-fhetch` (fhetch @ `8a3000a`, OpenFHE fork @ `c379d54`). (A GitHub source zip has empty submodules and can't be built; clone with submodules instead.) Build: `export OPENSSL_ROOT_DIR=$(brew --prefix openssl@3)`, then `make config-release`, `make build-release NUM_CPUS=3`, `make install-release` and `make install-cli`, which puts `fog` and `nbcc_fhetch_replay` in `~/.local/bin`. The build uses 3 parallel jobs instead of all 8 cores: heavy OpenFHE files take 2-3 GB each and this Mac has 8 GB. The build took 6.5 min. The only Homebrew addition was `ninja` (cmake and openssl@3 were already installed).
- **App code:** no source changes were needed. `build.sh` builds as-is against the native SDK.
- **One script fix:** `run_test.sh` read Python's `ru_maxrss` as kilobytes, but macOS reports it in bytes. Without the fix, "peak server memory" came out about 1000x too high on a Mac. It now converts on macOS.
- **Measured on this Mac (NREC=25):** `--cpu`, `--sim` and `--sim-full` all PASS with 0 era flips and max error at or below 5.6e-10. In `--sim-full`, all 25 records pass the bit-for-bit ring-level identity check. The server takes about 0.16 s on CPU and about 0.26-0.31 s under the simulator, with peak memory of 50 MB (CPU) and 97 MB (simulator). `tools/e2e_check.py` sent 10 random quizzes through the live `start_local.sh sim` services, with 0 flips. It needs numpy, which the base Mac Python doesn't have, so it ran from a throwaway virtual environment.

## Local-first, Fog-ready (v1.1, 2026-09-28)
The demo was finished and polished locally first. The Fog is a backend switch, and FOG.md is its guide.
- **Backend seam.** `services/backends.py` is now the only code that knows where the encrypted math runs. It has four backends: `cpu`, `sim`, `sim-full` (new: real-math record plus the bit-for-bit check on every quiz) and `fog`. Each one supplies `preflight()` (offline readiness check), `command()` (how `era_server` is launched), `describe()` (what the page shows) and `parse()` (extra facts from the server output, such as the Fog job ID). You choose one with `./start_local.sh <backend>` or `ERA_BACKEND`. The old `--mode` flag still works too.
- **The UI is backend-agnostic.** The page renders the backend's own `describe()` text. Before this change, `web/app.js` hardcoded the fog/sim/cpu wording. A unit test fails if the page ever branches on a backend id again. The badge color is keyed to `remote` (ciphertext leaves this computer), not to a mode name.
- **Transport timing (2026-10-02).** The compute service runs era_server through `run_timed()`, which timestamps every stderr line as it arrives. `FogBackend.timing()` turns the `[fog] assigned`, `[fog] upload …`, `[fog] upload complete` and `[server] replay done` lines into queue / upload / "remote run plus download" figures; `transport_ms` is the measured upload; the transport client reports upload progress but not when the response starts, so the download is counted in the remote-run figure. Local backends report `transport_ms: null` and the page shows "n/a". era_server now also reports `replay_ms` (time inside `replay()`) and `towers_out` (the result is compressed to one RNS tower by `run_circuit()`), and the compute service warns if a hollow backend's run was not hollow.
- **The Fog backend is the documented dispatch only:** `fog submit era_server <job> --hollow --target=$FOG_TARGET`. It never passes `--no-ring-dim-check`, and it is unit-tested offline.
- **Fail fast.** `start_local.sh` runs the backend preflight before making keys. `fog` without a login stops immediately and says what's missing and how to fix it. `make fog-ready` runs the `fog` CLI's own offline selftest plus that preflight.
- **Bug fixed: compute replied before reading the upload.** When compute refused a request (for example "unknown session"), it answered and closed the connection without reading the 2 MB ciphertext. The client saw a broken pipe instead of the refusal. Compute now reads the whole upload first.
- **Self-healing session.** If compute loses its sessions (a restart with an empty home, a new machine), the client re-sends the public keys once and retries, so an open quiz page keeps working. Tested live with all three local backends.
- **Bug fixed: double-tap skipped a question.** Two quick taps on an answer advanced twice and left a question unanswered, which would then fail at scoring. Picks are now locked during the 220 ms transition.
- **Polish:**
  - A "Try again" button appears after an error. Errors are plain language ("the scoring service isn't answering... Nothing unencrypted was sent.").
  - The server-log poller now stops on errors. Before, it ran forever after a failure.
  - A "Still working (N s)" note appears if scoring takes over 5 s, which matters for Fog queueing.
  - A "photo finish" line appears when the top two eras round to the same percent, with two decimals shown for those two, so the page never looks like a tie with an unexplained winner.
  - Answers can be entered with the keyboard (A-E / 1-5, Backspace to go back).
  - Old job files are pruned (the last 20 are kept).
  - `start_local.sh` refuses if its ports are already in use.
- **Checked in the browser:** a full quiz by mouse and by keyboard. The photo-finish sheet `[0,1,0,1,0,1,0,1,0,2]` gives 1989 81.88% vs The Life of a Showgirl 81.85%. Tested the error and recovery path (compute stopped, then back with an empty home, then Try again, which succeeded). Checked phone width (375 px) with no horizontal scroll on any screen.
- **Tests:** `make check` runs `run_test.sh --cpu/--sim/--sim-full` (NREC=25), then `make unit` (14 tests) and `make services` (the live two-process test for cpu, sim and sim-full). The twin needs numpy, so `make venv` creates a project `.venv` (gitignored) from `requirements-dev.txt`.

## Content and design v2 (2026-09-28)
Reviewed and approved in three rounds before implementation.

**Questions.** The v1 answers were album imagery in disguise ("glittering skyline" raised 1989's odds 3.2x; red, midnight, scarves, eyeliner, cowboy boots). v2 has 12 everyday situations: a risky text, canceled plans, a compliment, the camera roll, a group-chat fight, a free Saturday, a party, running into someone from high school, a forgotten birthday, texting style, a surprise $500, and the mic at a wedding. The answers are lowercase, in a texting voice, and use no lyrics, song or album titles, or album imagery. "before midnight" was reworded to "tonight" for that reason.
- **Mapping.** The same 8 traits, reinterpreted as personality: spotlight, feelings, edge, nostalgia, romance, homebody, main character, roots. Every answer moves 2 to 4 traits, so each one pushes toward a group of eras, never a single album.
- **Era profiles unchanged** (`eras.csv` is byte-identical). Balance comes from the answer weights only: a hand-written draft, then a bounded 0.1-step search. Signs and traits were fixed. New or rewritten answers could move at most 0.3 and previously approved ones at most 0.2. Every answer has a minimum strength of 0.6, so each one counts.
- **Result (full sweep of all 16,777,216 sheets):** each era wins 7.4-9.2%. We accepted this rather than nudging the profiles to reach exactly 8.3%. Near-ties (top-two gap under 0.001) occur on 0.63% of sheets, and the photo-finish line covers them.
- **Guessability.** For each answer I measured how much picking it multiplies the chance of its most-favored era. The worst case is "all caps" (Lover x2.85: about 7% becomes about 20%, so 4 in 5 people who pick it get a different era). The median answer is about x1.8, and the weakest is x1.3. The math is only somewhat less leading than v1 (worst x3.2, median x1.9). The bigger change is that no answer's wording points at an album.
- `tools/twin.py sweep` is now vectorized (4^12 sheets in about 1 s instead of a Python loop).

**No-leak rule (enforced in `web/app.js`, verified in the browser).** Before the reveal, nothing on screen depends on the winning era or on which era an answer favors:
- The top strip is the full catalog in a fixed order and fixed widths. v1 widened one block per question and the winner's block on the result; both are gone. The strip has no hover titles, so there's no color-to-era legend.
- Progress squares are neutral: black when answered, an outline when not.
- The scoring animation sweeps all 12 colors identically and ends with every block equal.
- The ranked scores moved from the pipeline (where v1 showed the winner with a star before Reveal) to after the reveal.
- **`/api/quiz` no longer sends answer weights.** v1 shipped each answer's trait deltas to the browser, where devtools could read them. The page only needs the text; the trait vector is still computed in `client_service.py`.
- A browser probe checked every rendered element after each of the 12 answers and during scoring. It found no era colors outside the strip, no era names in visible text, no tooltips, and the strip unchanged.

**Visual system.**
- Near-white (#f7f7f5) and black. One family, Archivo, at a narrow width for the display type. Mono only inside the proof.
- Square, flat controls. Answers are full-width ruled rows that flip to black on hover or pick.
- No cards, pills, eyebrow labels, gradients or shadows.
- Color appears in only four places: the strip, the scoring sweep, the reveal (the winner only) and the all-era bars (after the reveal).

**Flow.** Quiz, then a 3-step scoring screen (real timings, a real ciphertext slice, the 12-color sweep), then **Reveal**. The reveal wipes the page up into the winning color with the era name very large, the blurb, the runner-ups and a photo finish when it applies. Below it come the all-12 bars, then the strip as a divider, then **The proof**:
- Step 1, with "See the math" (the 8 trait values on personality scales) collapsed by default, plus the ciphertext hex, SHA-256 and download.
- Step 2: which backend ran, the ops, the scoring service's own log, and the returned ciphertext.
- Step 3.
- "Technical details" (CKKS, ring 2^16, slots, 128-bit, circuit, key sizes, backend, precision), collapsed by default.

**Decisions made while implementing:**
- Reveal text is black or white, whichever has more contrast for that era's color. All 12 pass WCAG AA; the lowest are Speak Now and evermore at 4.7:1.
- The scoring sweep runs for at least 1.6 s, even though local scoring takes about 0.3 s, so it can actually be seen. The steps show the real times, not the padded one.
- Long era names get a smaller display size. On phones, bar names wrap instead of truncating, and the trait scales stack as label, then scale, then ends.
- The winner's strip block sits directly above a hero of the same color, so it looks like the color pours out of the timeline. The strip itself is unchanged.
- Dropped: the optional "copy my result" line (not in the approved list). The status chips became one quiet sentence on the intro.

**FHE untouched:** `app/`, `services/backends.py`, `services/compute_service.py`, the CKKS parameters and the backend switch are unchanged. `client_service.py` changed only in what `/api/quiz` sends. `make check` passes on the new set: cpu, sim and sim-full at NREC=25 with 0 flips and the bit-for-bit check, 14 unit tests, and the live service test for all 3 local backends.

## Security hardening (v1.2, 2026-09-28)
A skeptical pre-publication audit (recording proxy on the client-to-scoring boundary, decrypt breakpoints, file and log scans, endpoint probes, repo scan) found no leak of keys or plaintext to the scoring side. It did find local-hardening gaps and some over-broad claims, fixed here:
- **Off iCloud.** The project and its niobium-client build moved out of the iCloud-synced Desktop into a local, unsynced development folder. Old run folders, which held demo secret keys, were removed and regenerated. The README now says to keep the project out of synced folders.
- **No plaintext on the command line.** `era_encrypt` now reads the 8-number trait vector on stdin: `echo u0,...,u7 | era_encrypt <home> <out>`. Before, the vector was an argument, and any process could read it with `ps`.
- **Owner-only key storage.** `era_keygen` sets `umask(077)` before writing, forces the client home to 0700, and sets `sk.bin` to 0600. The client service also runs with umask 077, so job ciphertexts are owner-only too.
- **Least material to the scoring side.** Only `cc.bin` and `rk.bin` are sent. `era_server` never reads `pk.bin`, and the recorded Fog trace package contains no public key. The scoring service now refuses `pk.bin` uploads as well as `sk.bin`.
- **Localhost hardening:**
  - The client service requires a Host header naming itself (blocks DNS-rebinding pages).
  - It refuses a foreign Origin, and requires `Content-Type: application/json` on POSTs, so a cross-site page would need a CORS preflight, which is never approved.
  - The compute service refuses any request carrying a browser Origin and requires `application/octet-stream` uploads. It checks this after draining the body, keeping the v1.1 broken-pipe fix.
  - `--allow-host` exists for a non-default hostname.
- **No third-party requests.** The fonts (Archivo, JetBrains Mono; SIL OFL 1.1, licenses included) are served from `web/fonts/` instead of Google Fonts.
- **Wording:**
  - The UI and docs now say "on this computer" and "the trusted local helper", not "your device".
  - "Never sent to the scoring service", not "never leaves this device".
  - Keys are "generated when the demo started".
  - The simulator is "a local rehearsal of a Fog run", not "the same trace the Fog executes".
  - "No quiz data leaves this computer" in local modes.
  - The material sent (`cc.bin`, `rk.bin`) is listed completely.
  - The key guard is described as a check for a file named `sk.bin`.
- **Personal details removed** from public files (names, email, machine paths). `.gitignore` gained `*.bin`, `*.fhetch`, `.fog/`, `.env*`, `*.log`, `.DS_Store` and conflict-copy patterns.

## Deliberate limits of v1
- For a public web launch, encryption and decryption would have to move into the visitor's browser (OpenFHE compiled to WebAssembly). In this version the trusted client is a helper program on the same computer as the browser, not the browser itself.
- One key pair per client-service start, shared across quiz retakes on that machine.
